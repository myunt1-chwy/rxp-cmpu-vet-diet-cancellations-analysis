#+TITLE: How do non-autoship reorders evolve for all aged customers?

* Inputs and definitions
Uses certified RxP prescriptions and shipment/line measures, plus ECOM
order history. Study cancellations: [2026-05-01, 2026-08-01) UTC;
observation cutoff: 2026-10-28 00:00 UTC. Windows: 7 through 70 days.
The original cohort requires vet-diet lines linked by Rx ID and customer
to CMPU, CUSTOMER_UPLOAD vet-diet prescriptions with an aged-order reason.
Original aged lines have no autoship restriction. Later matching lines
require a FALSE line autoship flag. Missing transaction rows imply FALSE;
present NULL flags are excluded and audited.
The order autoreorder flag is ignored. Cohorts and windows overlap.
A successful later order has no line with X status, recorded cancellation
reason or cancellation timestamp, and no unknown line status. Matching uses
numeric customer ID, non-null pet ID and exact nonblank part number on a
different order. Placement is strictly after the matched cancellation and
at or before the inclusive window end. Each anchor needs complete follow-up.
All-aged customers retain every qualifying aged anchor. First-order cohorts
retain only the unique earliest observed qualifying order, determined from
ECOM history with missing-history and timestamp-tie checks. The first-upload
history includes CUSTOMER_UPLOAD vet-diet prescriptions across sources;
the first-vet-diet history includes all channels and prescription sources.
Physical lines and shipment contributions are deduplicated before aggregation.
Conflicting physical-line flags fail validation, including FALSE/NULL mixes.

* Supplementary 70-day reorders
The supplementary initial-autoship table uses the earliest recorded shipment
for each subscription_key/product_key pair in the transaction source, with
a TRUE line-level autoreorder flag. The order-level first-shipped flag is
not used. Full shipment history is scanned for relevant pairs, without
study-window or cohort restrictions. All earliest-timestamp ties qualify.
Missing keys/timestamps are excluded; unknown eligibility is audited.
The raw result includes physical-line history for independent reconciliation
of pair minima. Existing command names remain stable for reproduction.

* Shipped matching lines
Later matching physical lines require =reorder_shipped_utc IS NOT NULL=,
where the timestamp is =MIN(ORDER_LINE_SHIPPED_DTTM)=. This requirement
applies to all reorder comparisons under section 3.1. Windows still use order placement;
original aged lines and cohort denominators have no shipment restriction.
Table captions describe eligibility in plain language.

* Common line-item eligibility and presentation
Every later matching physical line must satisfy
=MIN(ORDER_LINE_SHIPPED_DTTM) IS NOT NULL=, grouped by
=(order_id, order_line_id)=. A shipped sibling line never qualifies an
unshipped matching line. Existing order cancellation and unknown-status
exclusions remain. The baseline cancellation cohort is not shipment-filtered.
All cumulative panels use days, customers, cohort percentage, orders,
distinct line items and matching-line net sales. Line items are deduplicated
across shipments and original anchors. Shared presentation code lives in
shared/python/analysis/reorder_panels.py; captions describe eligibility in plain language.

* Subscription transaction source
Line-level autoreorder classification now comes from
=EDLDB.BT_SHARED_DW.FCT_SUBSCRIPTION_ORDER_LINE_TRANSACTION=, joined on
=ORDER_LINE_ID= for both aged and later lines. The extract retains
subscription group/key, order/product keys, one-time-shipped, auto-added,
and PBFresh subscription flags. Transaction rows are aggregated before
joining shipment records; conflicting keys or flags fail validation.
Missing transaction records imply FALSE; present NULL flags stay unknown.
Original flags do not restrict cohort membership.

Both the order autoreorder flag and the order first-shipped flag are ignored.
Initial shipments use transaction ORDER_LINE_SHIPPED_DTTM (TIMESTAMP_LTZ).
UTC conversion precedes the NTZ cast so Eastern display and daylight-saving
changes do not alter instant comparisons. Shipment sales still come from
=EDLDB.BT_HCA_HCDM.ORDER_LINE_COST_MEASURES_RXP=.
The existing successful-order and shipped-physical-line rules are preserved;
the example's optional auto-added/one-time-shipped filters are not applied.
Schema inspection SQL is =src/sql/subscription_transaction_schema.sql=.
The validated extraction is =data/current/source.parquet=, with SQL,
parameters, source hashes and reconciliation alongside it. Execution SQL
has indentation removed to stay within the runner's formatting token limit;
the runner re-formats the same statement in its query history.
