#+TITLE: Same-pet, same-product reorders

* Question
What percentage of customers come back and place a successful vet diet order
for the same pet and part number after an aged order in the next 70 days?

* Reproduction commands
#+begin_src sh
make same-pet-product-returns
make same-pet-product-returns REPRO=1 FINAL=0
make same-pet-product-returns REFRESH=1
#+end_src
Default builds use validated cached financial-return inputs. REFRESH=1
propagates to the shared extraction pipeline; no refresh is needed for
this layout change.

* Structure and outputs
Three cohort paragraphs own their tables and numerical summaries. Their
ordered IDs are declared in target.yaml. This parent places their outputs
side by side on one landscape page. Shared methodology is in the parent
financial-impact introduction.
The existing denominators, observations and study parameters are unchanged.
Outputs: outputs/latex/content.tex, assembled into the draft report.

* Panel alignment
Headings and summaries share the first layout row. Tables share a second
row so their top rules align automatically without fixed-height spacers.

* Shipped matching lines
Later matching physical lines require =reorder_shipped_utc IS NOT NULL=,
where the timestamp is =MIN(ORDER_LINE_SHIPPED_DTTM)=. This requirement
applies to all reorder comparisons under section 3.1. Windows still use order placement;
original aged lines and cohort denominators have no shipment restriction.
Table captions describe eligibility in plain language.

* Shared notes
Common methodology is documented once in the financial-impact introduction.
Tables reference that section and retain comparison-specific eligibility descriptions.
