#+TITLE: Non-autoship same-pet, same-product reorders

* Question
How do non-autoship reorders for the same pet and product evolve for customers
whose first Chewy order aged?

* Inputs and definitions
Uses certified RxP prescriptions and shipment/line measures, plus ECOM
order history. Study cancellations: [2026-05-01, 2026-08-01) UTC;
observation cutoff: 2026-10-28 00:00 UTC. Windows: 7 through 70 days.
The original cohort requires vet-diet lines linked by Rx ID and customer
to CMPU, CUSTOMER_UPLOAD vet-diet prescriptions with an aged-order reason.
Original aged lines have no autoship restriction. Later matching lines
require a FALSE line autoship flag. Missing transaction rows imply FALSE;
present NULL flags are excluded and audited.
The order autoreorder flag is ignored. Cohorts and windows overlap.
A successful later order has no line with X status, recorded cancellation
reason or cancellation timestamp, and no unknown line status. Matching uses
numeric customer ID, non-null pet ID and exact nonblank part number on a
different order. Placement is strictly after the matched cancellation and
at or before the inclusive window end. Each anchor needs complete follow-up.
All-aged customers retain every qualifying aged anchor. First-order cohorts
retain only the unique earliest observed qualifying order, determined from
ECOM history with missing-history and timestamp-tie checks. The first-upload
history includes only CMPU CUSTOMER_UPLOAD vet-diet prescriptions;
the first-chewy history includes all channels and prescription sources.
Physical lines and shipment contributions are deduplicated before aggregation.
Conflicting physical-line flags fail validation, including FALSE/NULL mixes.

Default builds

requires browser SSO and compatible existing financial-return inputs.
Refresh stages extraction and validation before replacing usable inputs.

* Outputs and dependencies
Each paragraph owns outputs/tables/table.org and outputs/latex/visual.tex.
The all-aged paragraph owns the shared query and data/current cache,
including raw records, query, manifest and reconciliation. Other paragraphs
declare this data dependency. The cohort parent groups six reorder types over
two landscape pages.
Net sales preserve signed amounts; missing sales are disclosed. First-order
classification reflects available historical records and snapshot channels.

* Shipped matching lines
Later matching physical lines require =reorder_shipped_utc IS NOT NULL=,
where the timestamp is =MIN(ORDER_LINE_SHIPPED_DTTM)=. This requirement
applies to all reorder comparisons under the medium-term reorder subsection.
Windows still use order
placement;
original aged lines and cohort denominators have no shipment restriction.
Table captions describe eligibility in plain language.

* Common line-item eligibility and presentation
Every later matching physical line must satisfy
=MIN(ORDER_LINE_SHIPPED_DTTM) IS NOT NULL=, grouped by
=(order_id, order_line_id)=. A shipped sibling line never qualifies an
unshipped matching line. Existing order cancellation and unknown-status
exclusions remain. The baseline cancellation cohort is not shipment-filtered.
All cumulative panels use days, customers, cohort percentage, distinct
line items, orders and matching-line net sales. Line items are deduplicated
across shipments and original anchors. Shared presentation code lives in
shared/python/analysis/reorder_panels.py; captions describe eligibility in plain
language.

* Report grouping

the same cohort.
The report preserves the 7-day increments through 70 days and the shared
methodology reference to section 3.2. Data ownership and commands are stable.
