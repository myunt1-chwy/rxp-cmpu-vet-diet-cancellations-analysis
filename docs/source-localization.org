#+TITLE: Target-local source ownership

* Ownership rule
A SQL query belongs to the analysis command that renders it. Importing utility functions from that command's Python module does not make its query a shared source. Genuinely reused Python helpers and generators for multiple report paragraphs remain shared. All five Mermaid definitions already live in their owning paragraph's src/mermaid directory; their renderer is shared across those five targets.

The canonical registry is shared/source-ownership.yaml. SQL compatibility links and Python module imports use that registry. Source moves preserve file bytes and query fingerprints, so cached results remain valid.

* Retained commands
Source-only command folders without target.yaml preserve existing analyses outside the report. Their included Makefiles own their command recipes. They do not introduce new report sections, questions, or numbering. Their README.org files describe the retained command; the document HOWTO continues to follow the report hierarchy.

* Remaining shared code
- Financial follow-up generators and SQL serve multiple return-comparison paragraphs and cohort variants.
- Contact and upload-state Python modules provide helpers used by several targets; their single-analysis extraction queries are target-owned.
- Reorder prescription, upload, contact, and history Python helpers have cross-analysis imports. Their extraction queries belong to the corresponding retained command.
- Markdown/LaTeX formatting, paths, SQL rendering, provenance, report assembly and multi-target diagram rendering remain shared infrastructure.
- Unused legacy approval_time_analysis.sql and cmpu_first_order_comparison.sql have no single consuming target; this move does not invent an owner or delete them.
