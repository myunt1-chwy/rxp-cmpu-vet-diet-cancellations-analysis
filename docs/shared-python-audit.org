* Shared functions after the split
The original three libraries and compatibility registry remain, alongside seven named helper modules:
- contact_analysis.py: reused contact query rendering and evidence analysis.
- reorder_analysis.py: reused matching and exact-money analysis.
- first_order_cohorts.py: source identity and first-order scope definitions.
- follow_up_tables.py: common retained-table parsing and source metadata.
- sql_listing_format.py: token-preserving SQL display formatting.
- latex_table_rows.py: replace computed rows without changing analyst prose.
- financial_values.py: date parameters, numeric identifiers and exact Decimal amounts, extracted from the baseline target so the new shared helpers do not depend on a generator. The existing ValueError contract for invalid money is preserved.

No analysis entry point remains in shared/python. The source validator rejects create_/recreate_ generators and main functions there. The source registry preserves established imports and CLI module names, while production consumers import common helpers directly. Target metadata declares reachable shared and cross-target code dependencies.

* SQL and reproduction
Four exclusive first-order follow-up queries and four driver-only audit templates moved with their consumers. Common query rendering remains shared where multiple analyses use it. Embedded contact-summary SQL is now a complete file with scalar-only parameters. Reorder matching predicates moved from Python strings into Jinja branches; distinct physical-line counting uses an explicit CTE compatible with the local audit engine. The extraction-query identities used by retained warehouse data remain unchanged.

The existing Make commands are preserved; batch-command recipes now live with their owners. Root HOWTO remains generated from report-target READMEs. This is source-ownership cleanup, not a warehouse refresh or a new analytical result.
